## 变更

- **B03-T01 领域 ADR 与共享类型**：`docs/jev-v2/ADR-B03-domain.md`、`worker/src/domain.ts`
  （`canonicalJSON`、`contentHash`、`objectivePayload`、`snapshotCompleteness`、
  `resolveField`、`effectiveView`、角色枚举与大小上限）。
- **B03-T02 content/personal 双层 revision**：`0011` 为 `links` 增加
  `content_revision` 与 `personal_revision`；`domain.ts::objectivePayload` 物理排除
  note/why/status，因此 note-only 不改变内容 hash。
- **B03-T03 快照 block 结构**：`evidence_snapshots.payload` 保存 block ID/role/text/
  URL/relation/acquired/时间/truncation；role 含 primary、author_continuation、
  quoted、external_article、third_party、legacy_unknown；重复 block id 拒绝。
- **B03-T04 不可变 QuestionSpec**：`question_specs` 以 `spec_id` 为主键，同 id 不同
  hash 返回 409 `spec_conflict`；`requested_model` 与 `display_only` 独立。
- **B03-T05/T06 run 与 decision**：`classification_runs` 追加保存 typed answers、
  usage、requested/resolved model、attempt、coverage、operation key；
  `current_projections` 由 `rebuildProjection` 从 run + overrides 重算，不新建 run。
- **B03-T07 幂等与原子提交**：run 提交与 override 均以 `operation_key` 去重；
  override 走 D1 `batch` 原子写入 overrides + events + personal_revision。
- **B03-T08 字段级 accept/reject/set_empty/reset + CAS**：`validOverride` 校验组合；
  `expected_revision` 不匹配返回 409 `revision_conflict`；`resolveField` 在重放后
  仍保留 reject，`set_empty` 与 `reset` 区分。
- **B03-T09 legacy override**：`source='legacy_unknown'` 与 `confirmed=0` 表示来源/
  确认行为未知，`effectiveView` 标记 reviewed 但不冒充已确认。
- **B03-T10 内部 v2 API**：`worker/src/domain-routes.ts` 暴露
  `/api/v2/links/{id}/evidence`、`/api/v2/question-specs[/{id}]`、
  `/api/v2/links/{id}/runs`、`/decisions`、`/overrides`、`/effective`，全部要求
  enricher token（App token 返回 401）。
- **B03-T11 扩展存储**：`entity_states`（not_run/failed/…）与 `budget_ledger`
  （单条/整体预算）已建表；B09 在此基础上实现算法。
- **B03-T13 删除级联**：所有领域表 `REFERENCES links(id) ON DELETE CASCADE`，
  测试断言删除链接后各表计数为 0。
- **B03-T14 迁移与回归**：`0011` 在空库与 0009 历史库顺序应用无错误；0009 未改动。
