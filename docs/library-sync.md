# 本地资料库同步（协议 1）

关联 #45、#46。Android 的 SQLite 保存完整列表、正文、翻译、整理后的正文、标签、备注和阅读状态；图片保存在应用私有 files 目录。旧 JSON 在同一数据库事务中迁移，提交成功后才移除源文件。未提交的收藏、人工整理和自定义标签仍使用已有持久操作队列和版本冲突处理。

## 服务端契约

`GET /api/sync?cursor=...&limit=20` 需要原有 Bearer 凭据以及 `X-Cairn-Sync: 1`、`X-Cairn-Tag-System: 1`、`X-Cairn-Content-Functions: 1`。粒度完整客户端另发送 `X-Cairn-Topic-Granularity: 1`。响应包含协议版本、数据库 epoch、mode、items、deleted、media、taxonomy、cursor、has_more；只有带 `X-Cairn-Sync: 1` 的响应才是本协议。limit 为 1–50。

当前服务是每个部署一份私人资料库，由部署的 CAIRN_API_TOKEN 授权，并不存在多租户行级账号表。游标以当前凭据和访问 origin 做 HMAC 签名，绑定数据库 epoch；没有嵌入 Token。Android 用完整服务器地址和完整凭据的散列隔离本地数据库、文件、操作队列及后台任务。换凭据不沿用原账号游标；旧凭据失效返回 401，篡改或其他授权域的游标返回 400。

0055 新增 `library_sync_changes`。序号使用 SQLite AUTOINCREMENT，由业务表触发器在业务事务内写入；事务回滚时事件也回滚。不依赖秒级时间戳。记录仅含 seq/link_id/kind/created_at，不复制被删除的正文、URL、备注或标签。链接、人工覆盖、自动分类结果、实体状态、自定义标签及显示词表均纳入变更；图片写入同一路径后补记资源更新事件。正文整理沿用现有 body revision 触发器进入同一链路。

首次请求固定最高 link ID 和事件水位，按 ID 倒序扫描这个边界；这些行是读取时的当前投影，并非冻结的历史快照。基线最后一页仍返回 has_more=true，然后从初始水位重放 changes；期间发生的插入、修改和删除由重放补齐。客户端仅在基线和重放都结束后按缺失记录清理旧副本。

changes 在本次水位内按序号读取。响应是幂等当前投影和删除编号；同一链接可能出现多次，投影可能包含随后发生的更新，但后续事件仍会重放。不能只凭空 items 判断结束，必须使用 has_more。返回前再次检查保留水位，避免清理任务导致跳过已被截断的事件。

事件保留 30 天；维护任务原子推进 floor 并清理旧事件。过期水位、数据库 epoch 不匹配、无法重放的游标返回 `409 {"error":"reset_required"}`。客户端重新建立基线，保留未提交操作和旧资料直到核对完成。旧列表/详情接口继续可用。

## 媒体与本地事务

media 包含 link_id/key/version/bytes/content_type/available。version 使用 R2 ETag，资源不存在时为 missing、available=false。同路径字节变化会改变版本；图片 GET 的 If-Match 不匹配返回 412，禁止把新版本字节写进旧缓存。原有鉴权和私有缓存头继续生效。

SQLite 事务同时写入内容、删除、词表、媒体任务和下一游标。提交前比较所观察的本地 generation；迟到响应不能覆盖刚确认的本地操作。媒体下载独立于资料游标，下载成功后仅按精确 key/version 标记完成；进程退出、断网和失败保留未完成任务。原子文件写入、账号级清理代数和删除标记拦截清理后的迟到图片。重新同步回收旧媒体版本。

设置显示正文、图片待下载数、资料字节占用和最近资料更新时间。256/512/1024/2048 MB 是当前账号正文序列化数据与图片的下载额度，不含 SQLite 索引、空闲页和系统任务数据库等开销。空间不足或超过额度时保留已提交内容并停止新增下载，用户可以提高额度或清理资料。清理只影响当前账号资料，保留云端收藏及未提交操作，并暂停自动更新。

## 后台执行与兼容

WorkManager 持久保存联网任务：前台恢复时触发检查、联网约束解除后继续、后台至少 15 分钟周期检查。系统节电和厂家限制可能延后执行，不保证实时或精确间隔。默认仅在非计费网络下载图片，文字可用移动网络；用户可关闭此限制或自动更新。任务只保存账号散列和服务器地址，执行时读取当前凭据并校验账号，不把 Token 放进 WorkManager 输入。账号切换取消旧账号任务，进行中的响应在提交前再次校验。

新 APP 通过响应头发现服务端能力；旧服务继续使用前台列表分页和单条详情校验，不以旧分页缺失判断删除。新服务保持旧 APP 的列表、详情和图片接口。正文同步完成与图片下载完成分别显示。

## 验证入口

- Worker：`npm test -- --maxWorkers=4`，包括真实 D1 事务回滚、同秒更新、基线期间变更、游标篡改/换域/凭据轮换、清理竞态、词表/人工标签/实体和媒体版本。
- Android：`LocalLibraryInstrumentedTest` 覆盖 JSON 迁移、SQLite 游标事务、重启续传、迟到响应、过期基线核对、额度失败、媒体版本复用与删除、离线搜索。
- `tests/android-worker/run.sh` 包含原有 14 个独立进程的整理恢复阶段，以及 2 个真正 Worker/D1 的增量同步进程重启阶段。
- `device` 工作流在 API 26 和 API 35 运行全部设备测试及 Worker 联调；发布前须取得实际成功结果。
