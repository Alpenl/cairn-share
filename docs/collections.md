# 合集：围绕用途组织收藏

## 现状与选择

当前 Worker 以 D1 `links` 保存唯一收藏；`custom_tags`、`custom_tag_links`、`curation_overrides` 表达标签和人工整理，不应承载合集。`worker/src/library-sync.ts` 与0055迁移已有独立正文增量流；安卓 `OfflineReadStore.kt` 使用 SQLite 保存正文、图片队列和同步游标；`LibrarySync.kt` 负责前台/后台更新。NAS 网页使用 `internal/dashboard/web/js/{query,list,api,store}.js` 局部更新与摘要缓存。

合集独立建模，收藏可属于多个合集，不复制正文/媒体、不改变标签/收藏状态；普通合集管理与加入操作不启动模型任务。第一版由用户创建和维护，名称必填、说明可选、支持置顶、归档、恢复及删除撤销；不增加嵌套、协作或常驻智能规则；自动整理仅由人类点击发起，模型不能维护合集定义。以简洁图标和文字为主，封面编辑留待后续。

## 数据与接口

1. 新增0057：`collections`（客户端UUID、名称、说明、置顶/归档/删除状态、revision、创建/修改时间）；`collection_items`（合集/收藏联合键、顺序、合集内备注、加入时间）。外键保护身份；删除合集只软删合集，永不删除收藏。全库删除收藏才级联移除关系。
2. `collection_operations` 保存操作编号、内容摘要及成功版本。同一操作重试只执行一次；不同内容复用编号报冲突。集合revision为并发控制边界，所有写入原子比较预期版本并递增；批量加入/移出全成或全败。排序只在同合集生效。
3. `collection_changes` 仅记录实体ID和递增序号；删除关系保留删除事件。独立分页增量接口复用现有数据库epoch，与正文流分开，保证旧安卓/旧网页继续使用原协议。客户端在同一SQLite事务保存数据和游标；同步不能丢掉未提交操作。
4. `/api/collections` 查询；`/api/collections/:id` 读取；`/api/collections/:id/operations` 接收明确意图（create/edit/archive/pin/delete/restore/add/remove/note/move）；`/api/collections/sync` 增量流。APP与NAS各用原有鉴权入口，不暴露内部Token。输入长度、批次数量、分页均有边界。
5. 现有列表/搜索接入 `collection_id`，使用关系索引；合集按手动顺序浏览，全文搜索、标签筛选仍在合集范围内执行。列表缓存键必须包含合集身份，写入后失效；本地快速筛选对不支持的合集条件明确回源，不能误返回全集。

## 网页交互

左侧增加“合集”与少量置顶项；查看全部/新建在轻量弹层中。阅读页在原帖操作旁增加“加入合集”，支持搜索、多选及顺手创建。列表已有多选增加批量加入。合集视图显示名称、说明、篇数；管理中编辑说明、置顶/归档、调整顺序、合集内备注、移出及删除撤销。刷新局部区域，保持筛选、阅读位置和键盘焦点；加载失败保留现有内容，保存失败保留草稿。

## 安卓与离线

收藏页提供轻量合集入口，不增加长期占空间的筛选行；合集详情沿用收藏阅读。分享保存可选合集，默认不选择；保存成功后按返回的收藏ID加入。支持多合集、批量加入、排序、合集内备注、置顶/归档/删除恢复。

SQLite保存服务端副本、独立游标及持久待提交操作，按连接账号隔离。先落盘再显示“待同步”，网络失败/进程退出可续传；幂等编号重试不重复加入。远端版本冲突显示“其他设备已修改”，保留本机意图，提供查看最新、明确重试或放弃；不静默覆盖。删除后的合集不被离线旧修改复活。图片与正文继续复用原缓存，不另存。

## 实现与边界

关联任务：[Issue #52](https://github.com/Alpenl/cairn-share/issues/52)。新协议用 `X-Cairn-Collections: 1` 双向确认，旧服务不能静默忽略合集条件。第一版每个账号最多500个未删除合集、每个合集1000篇，单次批量100篇；名称80字符、说明/备注2000字符。容量拒绝不提交部分操作。

安卓额外使用 `collections.db`，保持现有正文/图片数据库和文件布局。服务器副本与待提交队列分开；每次写入先进入SQLite事务，再投递独立WorkManager任务，不阻塞正文/图片下载。账号变更隔离未提交选择；网络结果未知保留原操作编号，明确冲突才允许核对远端并重试或放弃。Web局域网HTTP地址使用Web Crypto生成UUID，保存后的旧列表响应不能覆盖新版本。

自动验收包含真实D1并发重试/隐私删除、真实Go→Worker→D1桌面和390宽度交互、Android SQLite原子回滚/隔离，以及重启进程后恢复已提交但丢失响应的操作。API26/35全量设备检查与正式签名覆盖升级作为发布门槛；上线结果另记录于运维工作区。


## 2026-10-05 扩展：采集即归类与人工发起的自动整理

- [x] 浏览器插件0.4.0直接列出少量使用中合集；多选随采集草稿/上传队列持久化，关闭弹窗、离线、已保存但归属响应丢失都能续传。账号切换清空旧选择；冲突保留待处理归属，不重新采集正文。
- [x] 合集定义的创建、读取、修改、删除由人类界面操作；自动整理服务只读取定义并生成/应用收藏归属，不能创建、改名、归档或删除合集。
- [x] 新增0058持久整理批次、逐收藏概率、审核状态及应用回执。用户点击“自动整理”才创建任务，默认“生成预选，审核后加入”，可明确选择“直接应用预选”。已有归属保留，不强制每篇归类；只对用户选择的已有使用中合集判断。
- [x] Jev复用现有Judge API、固定jev-1.13.0与扩展20次/UTC日预算。若干收藏与每个候选合集组成独立Noul，同一次请求批量判断；最多32个合集/32题，每批最多8篇。概率>=0.8作为预选，其他概率仍可查看，不伪造理由。额度不足保存进度并等待下一UTC日；响应未知不自动重发。
- [x] 预选绑定正文revision及合集名称/说明；写入回执记录原有与新增归属。正文或合集定义已变化时拒绝旧结果；直接应用使用生成时版本CAS，冲突转为待审核。审核可逐项改选/跳过；只加入，不自动移出原归属。应用留下独立幂等回执与新增关系记录，支持核对后撤销。
- [x] Web与Android提供任务进度、审核/直接应用及历史结果入口；插件专注采集时手动选择。真实D1、模型mock、浏览器及API26/35完整回归后统一上线；不为验收调用真实Jev或自动整理用户历史库。
