# Extension reservation protocol

`POST /api/v2/extension-budget/reserve` requires the internal enricher token. App credentials cannot grant calls. The body is `{operation_key, kind, item_ids, tokens, limits}`; the key is 64 lowercase hexadecimal characters, kind is `entity`, `rerank` or `evidence`, and IDs are 1–20 distinct positive existing bookmark IDs. No source text or search query is stored.

All extensions share one UTC-day budget per Worker/D1 deployment: at most 20 operations globally, 2 per bookmark, 1,310,720 reserved input tokens globally, and 131,072 per bookmark. The four `limits` values have names `max_calls_total`, `max_calls_per_item`, `max_tokens`, `max_tokens_per_item`. Callers may only lower these fixed ceilings. An operation with several candidates charges one global call and one call plus its entire token reservation per candidate. A logical controlled evidence fetch reserves zero model tokens; redirect/byte/deadline restrictions remain separate.

For the verified pinned Jev 1.13 model, every model attempt reserves its entire 65,536-input-token context allowance before HTTP, including unknown outcomes. This is a conservative reservation, not observed usage or a character estimate; output tokens are free under the [model contract](https://docs.typesafe.ai/models) checked 2026-09-23. Other model IDs need a verified bound before this protocol can support them. Ordinary classification and evaluation retain their own budgets and are outside this extension scope.

A D1 batch atomically checks all limits and existing links, inserts an anonymous `extension_global` row, and inserts `extension_item` rows into the existing `budget_ledger`. Global rows contain only a random key, kind, counters and a payload hash, never bookmark IDs or material. Link-bound rows are cleaned by the 0026 deletion trigger; the global charge remains, so deletion cannot refund consumption. No new migration is introduced; 0011 plus all existing migrations through 0026 are required.

Only a newly inserted reservation returns `{granted:true,reason:"reserved"}`. An identical key returns `{granted:false,reason:"already_reserved"}`; an altered payload returns 409. Exhaustion returns `{granted:false,reason:"budget_exhausted"}`. A lost grant response, network error, invalid acknowledgment, unsupported old endpoint or timeout must result in zero external calls. No refund is permitted: external execution may be unknown. A fresh process cannot reset D1. UTC midnight is an explicit fixed-window reset, not a rolling 24-hour limit.

Deploy the Worker endpoint before enabling the new consumer. Do not run an old consumer with extension flags enabled during rollback: it lacks this reservation requirement. No rollout or migration is performed by the code/tests. Result deduplication, durable rerank caching and the remainder of B09 remain separate open work; this protocol only makes each reservation grant at most once.

Verification: `npm test` includes authenticated HTTP/D1 tests for concurrent grants, per-item/global token caps, duplicate/conflicting keys, discarded responses, day boundaries and deletion. The companion Go integration starts five separate consumer processes against real Worker/D1 and local synthetic provider HTTP; it does not call a paid model.
