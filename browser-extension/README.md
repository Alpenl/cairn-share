# Cairn 浏览器收藏插件

0.7.0 接入 `cairn.alpenl.com` 使用的新 Go 资料库。升级时替换原扩展目录后重新加载，不要卸载；在网页「设置 → 状态与账户 → 浏览器插件」创建专用采集令牌，再粘贴到插件连接页。`cairn_c_` 令牌仅发送到新服务，旧令牌继续发送到旧服务，两库不自动同步。带版本或正文已确认的待同步任务必须先完成；其余待同步内容只有显式勾选转移才可切换。

浏览器本地 Defuddle 净读、去噪与 Markdown 转换后直接保存原文；服务器独立生成短摘要和 Jev 固定词表标签，不再为每条新采集生成整篇阅读正文。英文翻译在网页按需请求。相同正文不会重复触发模型任务；发生超时先核对保存回执。新服务单文件最多1 GiB、最多24张图片和256项媒体；不支持的内容保留本机任务并提示，不能伪装为已归档。


0.4.1 将正文与媒体分开同步：正文先保存，图片以二进制最多三路并行上传，视频/音频保留分片续传。重试先核对服务器回执，只补传未完成文件。采集时仍可选择合集。
“已保存在本机”代表等待同步，“已同步”才代表服务器已接收。可以关闭弹窗，后台继续上传。
同步失败会保留完整图文，可在待上传列表重试。保存完成后按钮会锁定，编辑备注可发起新的收藏。

默认采集当前页已加载内容；取消勾选可仅存链接。保存时会申请当前文章引用的媒体站点权限；缺少权限的收藏会在弹窗里提示“允许读取媒体站点”，
也可在设置页一次性允许读取所有网站的图片，以归档页面引用的 CDN 图片。权限未开启或图片无法获取时保留来源链接并提示缺失数量。
不会为了图片向目标站点发送 Cairn 令牌或登录 Cookie。

采集上限：正文约 90 KB、24 张图片、单图 16 MiB。图片不再占用正文请求的 Base64 配额。
提取正文后立即入队，跨站取图在后台执行。页面可读取的图片快照、已下载文件和上传进度存入本机 IndexedDB；跨站原图尚未下载时仍依赖来源可访问。最多 100 条待同步收藏；正文和描述信息约 24 MB，文件另受浏览器存储空间限制。未加载、折叠、嵌入 iframe 中的内容不保证采集。

新图文接口依赖 Worker 数据库迁移 0054 及配套服务更新。旧服务返回不支持时会保留本机队列，
不会悄悄降级成仅存链接。请先升级服务，再安装或重新加载本版本插件。

Chrome：解压 `dist/cairn-chrome-0.9.0.zip` 到固定目录，在扩展页开启开发者模式，加载已解压扩展。
更新现有安装时替换同一目录中的文件，然后在扩展页点击重新加载，已有令牌与待上传队列保留。
Firefox：`dist/cairn-firefox-0.9.0.zip` 可用于临时调试安装；长期安装需要浏览器认可的签名。

开发：`npm ci`、`npm run verify`；Firefox 原生验证：`npm run test:firefox`。
产物：`npm run build`。测试使用本地模拟服务器，不访问生产收藏库或调用真实模型。

权限和数据处理见 [PRIVACY.md](PRIVACY.md)。

## 0.9.0：GitHub 登录与自部署服务器

- 设置页「连接」在令牌输入框上方显示收藏库提供的第三方登录（目前是 GitHub）。点「使用 GitHub 登录」后在浏览器授权窗口完成登录，插件自动取得采集令牌，不必再到网页手动创建和粘贴；粘贴令牌照旧可用。
- 流程：插件生成 state 与 PKCE 校验串 → 收藏库 `/api/v1/auth/github/start?client=extension` → GitHub → 收藏库回调 → 带一次性授权码跳回 `identity.getRedirectURL()` → `POST /api/v1/auth/extension/token` 兑换 `cairn_c_` 令牌 → 走与粘贴令牌相同的测试并保存。授权码 2 分钟内只能用一次，必须配合本机的校验串。
- 只有登录账号在服务端 `CAIRN_AUTH_OWNERS` 中才会成功；取消授权、非所有者、过期会分别提示。待同步队列的换号规则与粘贴令牌一致，并在打开授权窗口之前检查，避免生成用不上的令牌。
- 服务端需把插件回调地址加入 `CAIRN_EXTENSION_REDIRECTS`；未加入时连接处不显示登录按钮，「更多 → 登录回调地址」会显示需要登记的地址。Chrome 的地址取决于扩展 ID，解压安装时请固定安装目录（或在 manifest 中设置 key）。
- 新增 `identity` 权限（Chrome 不额外提示）。登录提供方由收藏库决定，插件在 `src/auth.mjs` 的 `AUTH_PROVIDERS` 中登记名称和图标；以后加 Google 只需在服务端开启并在这里加一项。

## 0.8.0 标签与设置改版

- 弹窗在「合集」和「收藏原因」之间新增「标签」：第一次打开从收藏库拉取标签目录，连同词表版本存进本机 `storage.local`；之后直接读本机缓存，再只比对一次版本（`If-None-Match`，未变化时服务器回 304）。
- 收藏库词表有新版本时，刷新按钮出现红点并提示「收藏库标签已更新」，不会自动覆盖本机缓存，点「刷新」才更新；连不上服务时保留缓存并提示重试。
- 标签按使用次数分三档大小，带类型色点，可按类型筛选，超过约三行时折叠。可多选；「载体」这类单选类型只保留一个。选中的标签随收藏一起保存，作为人工确认的标签写入，结果提示会写明保存了几个标签。缓存过期后已归档或删除的标签会被服务端跳过，不会让收藏失败。
- 设置页改为单栏：连接（令牌收在「更换令牌」后面）、待同步、标签（本地数量、词表版本、上次同步、立即刷新、打开弹窗时检查更新、清除缓存）、采集（默认保存正文和媒体、保留完整链接、读取所有网站的图片，开关立即生效）、更多（批量补采、快捷键、隐私说明）。批量补采页沿用同一外壳。旧链接 `options.html#queue` 仍会定位到待同步。
- 标签只对 `cairn_c_` 采集令牌连接的新服务开放。旧令牌，以及还没有 `GET /api/v1/collector/tags` 的旧服务，弹窗不显示标签区，其余功能照旧。
- 先部署带标签接口的 cairn-go，再替换安装目录并重新加载 0.8.0，不要卸载；令牌、待同步队列与草稿保留。无需数据库迁移。

## 同文补采、视频与音频

再次采集同一篇文章会更新最早的收藏，保留编号、时间及人工整理。微信公众号临时参数、X/twitter 的同文地址与通用跟踪参数不会制造新收藏；其他查询参数和路由片段保留区分。保存成功后可点“重新采集”。原收藏已有图片而这次采集不完整时，保留原内容并提示重试。

视频/音频实际下载后以 8 MiB 分块归档，插件与后台不再设置 256 MB 单文件上限或每篇 16 项上限。X 通过选中帖子对应的公开媒体描述取得最高码率 MP4。普通文件可在阅读网页播放或下载。HLS 点播会连同音轨、播放列表、初始化片段和实际分片保存为 ZIP，下载后可在支持本地 HLS 的播放器播放；加密、直播、无法识别的 blob 播放器会明确提示尚未完成，不把外链视作已归档。

待上传媒体临时保存在本机 IndexedDB；关闭弹窗或后台重启后从服务器确认的分片继续，成功或移除队列后清理。完整文件下载前中断可能需要重新下载；未完成的分块上传会在过期前重建会话。本机空间不足、权限缺失或来源不可用时显示失败原因，正文保存与媒体归档的进度分别显示。


### 0.3.1 正文解析

正文提取复用 Defuddle 0.19.4，Markdown 转换复用 Turndown 7.2.4（GFM），DOMPurify 3.4.16 过滤可执行内容。所有依赖随安装包发布，仅在用户触发保存/预览后注入；关闭 Defuddle 的异步外部提取，不发送页面给 LLM 或第三方解析服务。X 仅处理当前帖，引用链接单列保存，保留多段正文。图片和媒体通过归档/续传流程保存。

## 采集时选择合集

弹窗直接显示使用中的合集，支持多选或不选。合集由你在网页/APP创建和管理，插件只选择归属。选择会随本机草稿和上传队列保存；正文保存后再加入合集，归属失败保留操作并可重试，避免重复采集。换账号时清空旧合集选择。版本冲突需点击重试确认按最新版本加入。

合集需配套0057/0058服务，插件通过能力确认防止旧服务忽略归属操作。自动整理在网页/APP由用户主动发起，默认审核；插件不会主动调用模型或改变合集定义。

## 0.5.0 批量补采

在弹窗或设置页打开“批量补采收藏库正文”，点击“一键采集所有待办”。首次需允许网站访问权限。
任务按本轮开始时的收藏 ID 范围分页扫描，无 100 条总任务截断；只处理缺少正文且未丢弃的收藏。
每次打开一个后台标签页，等待正文稳定后采集，再接入现有图文和媒体上传队列。
用户切换到采集页会暂停并保留页面；登录、验证和超时留下失败项，可打开原链接处理后重试。
部分网站需要前台交互，未展开、受限或未加载的内容仍需手动采集，批量采集不绕过访问限制。

面板关闭不影响任务；浏览器重启后暂停，可手动继续；扩展后台重启靠持久任务和定时唤醒恢复。
待上传队列达到容量时暂停采集，已有内容继续上传，腾出空间后可继续。
“已采集”表示已保存在本机，上传状态单独列出；完成一轮不代表所有媒体已上传。
更换令牌前必须完成或移除批量补采的待同步任务，避免把原收藏 ID 发到另一个库。

需先部署配套 Worker 的 `GET /api/captures/v2/pending` 列表/单项检查以及 `POST /api/captures/v2` 的 `target` 约束；无需新增数据库迁移。
批量上传绑定原 ID、完整 URL、正文及阅读版本，仅在原收藏仍缺正文时原子补全，不会新建收藏、恢复已删条目或覆盖其他设备的新正文。
已有手动采集更新流程保持不变。测试仅使用本地服务和模拟网页。


## 0.6.1 大文件媒体归档修复

- 插件和 Worker 同时移除视频/音频的 256 MB 人为上限，不改成另一个固定大小；取消每篇 16 项媒体、HLS 1000 分片与 1 MiB 播放列表截断。
- 文件按小块计算 SHA-256，HLS 用流式 ZIP64 打包，避免把整份文件转换为 JavaScript ArrayBuffer。下载有持续进度就继续；连续两分钟没有收到数据才超时。
- 先部署配套 Worker，再替换原安装目录并重新加载 0.6.1。不要卸载插件，以保留令牌、文件与待同步队列。原先因大小失败的收藏点击“重试”即可继续，无需重复采集正文。
- 大文件仍依赖浏览器可用磁盘、来源可访问性及 R2 平台能力；目前固定 8 MiB 分片协议最多受 R2 的 10,000 分片约束。无产品大小配额不表示物理资源无限。加密或未结束的直播仍会明确报告尚未归档。
- 该版本只调整视频/音频链路，正文与图片接口的边界见本文开头。无需数据库迁移，已归档文件与旧客户端保持兼容。若需回退，先恢复插件 0.6.0，再回退 Worker；超过旧上限且尚未上传完成的任务会保留在本机，重新升级后可续传。

设置页「连接」可填写自部署服务的 HTTPS 地址（只填来源，不带路径），回环地址允许 HTTP。点击「测试并保存」或「检查登录方式」时申请该主机权限。连接测试成功才保存新地址；切换服务会清理标签/合集缓存，待同步队列按服务器与令牌共同隔离，带旧资料版本的任务禁止转移。旧版无地址设置自动沿用原服务。

新版本新增 identity 权限用于第三方登录。Chrome 解压安装请保持原安装目录，不要卸载；将「更多 → 登录回调地址」显示的精确地址加入服务器 CAIRN_EXTENSION_REDIRECTS。Firefox 临时包仍需签名才能长期安装。
